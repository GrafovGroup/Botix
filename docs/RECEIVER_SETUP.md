# Private BOTIX receiver preparation

Intended mailbox: **info@botix.ca**. Ownership and external delivery are unverified. This implementation persists a private outbox; it does not send email or activate the website. Run `pnpm test` and `pnpm delivery:test` for offline synthetic evidence.

## Prepared service

`receiver/receiver.ts` validates authenticated, bounded JSON using the same inquiry schema, including consent and product/intent rules. It writes a mode-0600 temporary record, fsyncs it, atomically links the record under its stable idempotency key, and fsyncs the private directory before returning HTTP 202 with `{accepted:true,receipt:<key>}`. Retries return the same receipt; changed payload returns 409. A storage error returns 503. There is no success response before durable acceptance. Concurrent requests and process recreation are tested. A disk/power-loss drill is not claimed.

`pnpm exec tsx scripts/run-receiver.ts` is the prepared HTTPS service, bound to loopback by default. It is not part of the Next app or its startup. Supply private `RECEIVER_TLS_KEY`, `RECEIVER_TLS_CERT`, `RECEIVER_OUTBOX`, `INQUIRY_WEBHOOK_SECRET`; optionally `RECEIVER_HOST`/`RECEIVER_PORT`. Outbox must be an absolute, owner-only directory outside all document roots and deployments. Provision owner-controlled TLS/ingress and shared rate limiting before exposure. No keys, mailbox passwords or certificates are included. The adapter retries at most once on ambiguous network/502/503/504 errors with the same key and body, and requires the matching durable receipt. Legacy receivers must adopt this acknowledgement contract before enablement.

## Activation sequence (not performed)

1. Verify control of info@botix.ca and identify accountable recipients, support coverage, privacy contact, retention period and staff access. Store credentials in a private secret manager. Do not change WHC mail routing/DNS silently.
2. Provision the private service, restricted outbox permissions, verified TLS, authenticated ingress and shared rate limiting. Confirm persistence across restart, disk-full failure, backups and restore. Never serve the outbox over HTTP. Alert on non-PII counters: pending age, acceptance failures, storage capacity, authentication failures. No body, contact, token or secret logs.
3. Connect an approved mailbox worker/CRM to pending records. Route **To: info@botix.ca**, use a verified BOTIX From identity and the validated customer email as Reply-To; never use user text as raw SMTP headers. Keep purchase/rental/pilot/integration/service/general as structured labels. Prefer plain-text templates and escape any HTML. Mark sent only after transport acknowledgement. Use the receipt as a stable message ID; reconcile uncertain sends before retry because SMTP cannot guarantee exactly-once delivery. This downstream transport remains intentionally unconfigured until credentials/provider are approved.
4. Obtain explicit authorization for a synthetic mailbox test. Use .invalid identities in offline tests; for real mail transport use only the owner's explicitly designated test addresses. Confirm inbox/spam routing, reply-to, one accepted record per duplicate, delivery failure alerts and the EN/FR receipt language. No external email was sent in Phase 2.
5. After receiver and actual mailbox verification, obtain separate live activation approval. Set existing readiness attestations only with evidence. A later deployment must update the disabled-only release preflight deliberately; do not bypass it with an environment toggle. Staging remains delivery-disabled.

Operator triage: inspect authorized private records, classify intent, confirm task/site/date constraints, identify missing evidence and respond in the recorded locale. Do not promise inventory, availability or deployment capability. Share with suppliers only under the approved privacy/consent process. Follow an approved deletion/backup retention schedule; retain deduplication evidence long enough for challenge/retry reconciliation. Avoid exporting lead bodies to GitHub.

Receipt wording means durable receipt for review, not delivered email or a confirmed quote/booking. The existing browser receipt and failure language remain bilingual. Detailed external email, abuse/load, restore and mailbox tests are pending authorization/infrastructure, not reported as passed.
